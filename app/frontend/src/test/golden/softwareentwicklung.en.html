AI in Software Development

Marvin Jakob Updated: 16 November 2026 · approx. 4 min read

Modern Software Development

AI can be used most effectively when its results are easy to verify. In mathematics, for example, proofs or counterexamples can confirm or refute a solution. In software development, executable tests help to determine whether an implementation delivers the expected results. AI has now become so good at software development that our evaluation of the results can no longer keep up.

AI can do more than write code: it can also create tests, find errors and implement fixes. For people, clear requirements, suitable verification methods and the design of the entire development process are becoming more important. The more reliably results can be verified, the more work steps agents can take on independently. This fundamentally changes the work in software development.

““This is the way!”– Din Djarin

There is no way around clearly understanding what we actually want and, perhaps more importantly, why. Once we can describe that precisely, it is time to let AI loose on the problem. Here I would like to present an approach in which we humans focus on the content and leave as much of the routine work as possible to the machine.

To let as many agents as possible work simultaneously, I have divided them into three teams. The first team, made up of experienced test analysts, breaks the requirements down into scenarios and writes Fidelity Tests. The software we build should behave exactly as described in the requirements. To achieve this, the Fidelity Tests capture flows, edge cases and error handling based on the reference scenarios created. These kinds of tests are easier for an AI to verify. Verifying them is then the job of the second team of skilled test agents. They run the tests on the code written so far, one by one, and create feature and bug tickets. If a tester finds a deviation from the described behaviour, it is documented in the backlog. The desired behaviour is also recorded as a ticket. In this way, an internal backlog gradually fills up as the basis for a third team. The fixers each pick up one bug ticket and chew on it until it is solved. Before a fixer commits to any code, it is passed through a Merge Gate. All resolved tickets must not only solve the actual problem but also meet minimum standards for code quality and security.

The productivity of our agents leads to a large number of commits, which are combined in a branch for each release. Before we publish anything, we make sure in a final test that our release actually works cleanly. The push to the repository only happens at the very end.
